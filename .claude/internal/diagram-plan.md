## 评判标准（一张图该不该存在）

图必须在 30 秒内做到文字做不到的事，只允许四种形状：

1. **状态机**：时间 + 条件分支多（生命周期、跨链三阶段）。
2. **分流树**：比例 + 去向多的资金/费用流（四池、费用分流）。
3. **原子多方时序**：同一笔交易内借-还-到手（YT Flash Swap）。
4. **失败路径瀑布**：正常路径 + 多个失败分支 + 各自处置（POLend 结算、跨链失败）。

反例（不画）：线性流程（有序列表更清楚）、静态对照（表格更清楚）、概念循环（ASCII/链接更清楚）、低流量页配图、装饰插画、未定版 UI 截图。

配套纪律：每个机制页至多 1 张主图；跨页复用靠链接不复制；图承担后，正文对应冗余段落应删减；图不重复正文。

## 通用规范（每张图必须满足）

1. 主标签用用户语言；**函数名 / 变量名 / 错误名不上图、不上公开书正文**（只允许出现在本文件的「真相源」栏）。现状违反此条：`polend.md:37` 与 `flywheel.md:78` 的瀑布图。
2. 数字分两类标注：合约固定常量标「固定」；owner 可调参数标「当前默认，可由协议方调整」。时长/比例类合约常量用绝对锚点表述（365 天、90 天、24 小时、1%），不写「约」；「约」只用于人工触发的时点（如周期结算实际发生时间）与实际成交结果（预算 vs 实际建池）。禁止绝对化措辞，图完成后跑 `bash scripts/check-absolute-words.sh`。
3. 中文全角标点；uAsset / POL / PT / YT / Hook / POLend / Preorder / GenesisCredit 等术语保留英文；示例用泛指「用户」「某 Memecoin」。
4. Mermaid（flowchart / sequenceDiagram / stateDiagram-v2），每图配一句图注「这张图读什么」；不用 xychart（GitBook Mermaid 兼容风险），曲线类信息用小表格。
5. 被替换的旧图同次提交删除，不留孤儿。

### B-3 `P0` Memeverse 跨链三阶段失败状态图

- 页面：`memeverse/omnichain.md`（新建；把「跨链的可靠性」表格升为图，表格保留作对照）。

- 内容规格（stateDiagram，每状态标注源链/目标链余额变化）：
  - 发送（源链）：消息费不精确 → 当笔回退、资金不动；金额低于最小精度 → 回退；非最小精度整数倍 → 截断部分发送、余量当笔退回。
  - 到账（目标链铸造）：目标链暂时无法接收 → **不撤销源链**、消息在目标链重新投递；接收预算配置过低 → 「已发出、未到账」滞留（源链已销毁、目标链未铸造），资金不丢、需手动恢复——标「极端配置类，少见」。
  - 落位（质押 / 收益分发）：目标收益库不存在（治理链未就位或创世失败）→ 到账的 Memecoin **直接给接收人**（裸币，无份额无票权），可在收益库就位后重新发起；落位本身失败 → 退回可重试。
  - 结论标注：「发送成功 ≠ 到账 ≠ 质押成功」；到账后**核验收益库份额，不是核对代币余额**。
