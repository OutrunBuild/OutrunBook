Note: `/tmp/render-diagram.py` renders every diagram blank (it loads the SVG via `<img src="file://…">` from a `set_content` page; Chromium blocks file:// subresources — verified with four-pools.svg too). For this review the SVG markup was inlined into the page instead; do the same for future rounds until the script is fixed.

## P1

- [颜色搭配] 4 of 5 edge labels are invisible in the standalone SVG — "Epoch ends", "Within the window", "All three conditions hold", "One missing: full rollover" render as solid white slabs with no text. Cause: the exporter flattened `.t-muted { fill:#ffffff }` (dark-theme text color) onto `.c-mask { fill:#ffffff }` (light-theme mask color) — white text on white pill. The HTML deliverable is unaffected (themed CSS vars, labels legible). Only the fifth label ("Re-allocated next epoch", `.t-database` purple) is visible, which makes the four blank slabs look like rendering garbage. → Export script theme flattening: resolve ONE coherent palette — when `c-mask` flattens to a light fill, flatten `t-muted`/`t-dim` to dark ink (e.g. #334155) — then re-export the SVG. (src JSON labels are fine.)
- [箭头形状] `gate→rollover` ends `L 155 243 L 136 243` exactly on top of the `claim→rollover` edge (`M 167 243 L 136 243`): 19 units of exact line overlap and both marker-end arrowheads land at the identical point (136,243) on "Into treasury"'s right side. Two different flows (unclaimed-claim vs gate-fail rollover) read as one edge with one arrow. → src JSON `via`: approach "Into treasury" from its bottom side (toSide bottom) or offset the approach y by ≥10 from the claim edge.
- [排列布局] The two reciprocal long edges run parallel 5 SVG units apart (5.7px at 820px page width) for ~500 units across the entire diagram bottom: `gate→rollover` at y=300 and `rollover→gate` at y=305, opposite directions. At page size they read as one smudged double-line bus / rendering artifact. → src JSON `via`: separate them clearly (e.g. y=292 and y=316) or collapse to a single shared bus with one label.
- [排列布局] Edge routing invades the legend block. The purple dashed route runs at y=305, i.e. exactly at the "Legend" heading baseline (y=304), cutting the heading off from its swatch row (y≈324); the "Re-allocated next epoch" pill (y 310–324) sits precisely on the legend-entry row height, so it reads as a third legend item. → src JSON: keep the return route inside/just below lane 2 (see fix above); export script: reserve vertical space so the legend block starts below y≈330.
- [图形错误] Node text overflows box interiors — zero padding, glyphs touching/crossing the box strokes: "by vote share, self-claim" (~109.5 units of text in a 106-unit box, crosses both strokes), "enrolled / revenue / votes" (~114 vs 110, crosses), "Settle the epoch" label (105.6 vs 110, ~2-unit clearance), "no votes; counts in base", "25% default; governance-set" (edge-to-edge). → src JSON: widen the four tight nodes ~15–20 units, or export script: fix font-metric measurement (assumes ~0.55em advance; JetBrains Mono is 0.6em) / add horizontal padding.
- [图形错误] The semantic sigil collides with the first letter of the label on all 8 nodes ("Stake shares" glyph on the "S", "Delegate votes" on "D", "Vote this epoch" on "V", "Settle the epoch" on "S", "Into treasury" on "I", "Active claim" on "A", "Allocate rewards" on "A", "3-condition gate" on "3"); on "Settle the epoch" it is also clipped by the rounded corner. Text stays readable but every node shows a glyph smudge on its first letter. → export script: give the sigil its own row above the label, or left-align label with a sigil gutter, or shrink sigil + add left padding.

Under the delegate node it reads as "delegate → but no votes". → src JSON sublabel: e.g. "undelegated: no votes, still counts in base", or move the fact to the "Stake shares" node.

Worst combined with the overflow items above. → src JSON/export: raise sublabel font to ≥8 units or reduce viewBox width. (Better than sibling diagrams whose 1080 viewBox renders 8px text at ~6px — but still squint territory.)
