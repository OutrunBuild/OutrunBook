# omnichain-stages review (round 1)

Reviewed: assets/diagrams/omnichain-stages.svg (source: assets/diagrams/src/omnichain-stages.lifecycle.json, rendered HTML: assets/diagrams/omnichain-stages.html) at 820px and 1100px; cross-checked against memeverse/omnichain.md and the light-theme HTML render to separate "broken export" from "intended design".

Context that frames every finding below: the HTML page renders this diagram correctly (light theme, `var(--mask)`, `var(--text-dim)`, dark text on tinted boxes). The standalone SVG — the exact asset `memeverse/omnichain.md` embeds — hardcodes a self-inconsistent theme: mask/background surfaces resolved to the LIGHT value (`#ffffff`) while all text classes resolved to DARK-theme values (`#ffffff` fill). Result: white pills with white text, pastel boxes with white text.

## P1

- [图形错误] `.c-mask { fill: #ffffff }` in the standalone SVG paints every edge-label backdrop as an opaque white pill, and the label text on it is `.t-muted { fill: #ffffff }` — white on white. All 7 transition labels are invisible in the embedded asset: "Full amount sent", "Non-integer multiple: truncated, remainder refunded", "Fee inexact / below minimum unit" (+note), "Arrived", "Placement fails" (+note), "Budget too low (extremely rare)" (+note), "YieldVault does not exist" (+note). Verified in HTML source: `.c-mask { fill: var(--mask) }`, `.t-muted { fill: var(--text-muted) }` — the export script flattened theme vars to opposite themes. This kills the diagram's entire failure-path storytelling (fee revert, budget stranding, vault-missing). → export script: resolve all `--*` vars to one self-consistent theme (dark masks like `#0f172a` with light text, matching the dark-grid style).
- [颜色搭配] Same root cause, node surfaces: each node draws an opaque white `.c-mask` rect under a 40%-alpha color fill (e.g. `rgba(6,78,59,0.4)` over white ≈ rgb(155,184,177)), then draws `.t-primary`/`.t-muted` text in `#ffffff` on top. Measured contrast ≈ 2.1:1 (active boxes), ≈ 1.9:1 (success), ≈ 1.8:1 (failure boxes) — all 8 node titles and sublabels are white-on-pastel, far below 4.5:1; at 820px the sublabels are smudges. On the dark page background the boxes also glow pastel-light against the dark grid, unlike any other surface in the style. → export script: mask must resolve to the dark panel color so fills stay dark and white text keeps ~12:1.
- [排列布局] The `send-receive-cut` channel line (horizontal at viewBox y=98, x 104–238) strikes straight through the lane-01 band label "01 / The three cross-chain stages" (text x 72–270, baseline y=100) at mid-glyph height. Confirmed visually at 820px, 1100px, and in the light-theme HTML render — it is source geometry, not an export artifact; the band label reads as struck-through text. → src JSON (or lifecycle renderer): route the top-channel at y≤88 or shift the band label below its dashed rule.
- [字体] At the standard 820px embed width (viewBox 980 → scale 0.837) no text reaches legible size: edge labels 8px→6.7px rendered; sublabels, edge notes and step chips 7px→5.9px; node titles 9.6–10px→8.0–8.4px. The two labels that carry the diagram's hardest semantics ("Non-integer multiple: truncated, remainder refunded" at 6.7px, "YieldVault does not exist / Retry once it is in place" at 6.7/5.9px) are the least readable. → src JSON/renderer: raise edge-label/note font sizes or shorten labels; node sublabels need ≥9px source (≈7.5px at 820) minimum.

## P2

- [箭头形状] "Arrived" label (viewBox x=356, y=202; mask 333–379 × 191–207) floats in empty space ~45px below the receive→settle hop (which runs at y=157) and ~23px left of the settle-return drop — it is bound to no line, so a reader cannot tell which transition it names. → src JSON: move `labelAt` onto the hop (e.g. [325,146]) or drop it (the rail already implies arrival→placement).
- [箭头形状] The retry loop `return-settle` terminates at exactly (343,157) — the same point where the forward `receive-settle` hop lands — so the two arrowheads overlap pixel-for-pixel on Placement's left edge; the loop-back re-entry is visually indistinguishable from first-pass flow. → src JSON: give the loop a distinct entry point (e.g. toSide left at y≈172).
- [产品语义] Lane 02 is named "Waiting and retries" but contains only the placement-retry loop. The arrival-stage wait/redelivery mechanic — a headline of omnichain.md ("the protocol does not roll back the completed send; the message is redelivered on the destination chain", "source not rolled back, redelivered automatically") — appears only in the bottom card, not in the graph; the one lane named for waiting does not contain the one true waiting state. → src JSON: add a "Queued for redelivery" state in lane 02 fed from Arrival, or rename the lane.
- [排列布局] `send-revert` exits Send at its left-edge midpoint x=35 and drops straight down at x=35 — exactly the node's border x — so the line merges with the box stroke for the lower ~30px of the box before continuing; it reads as the box outline extending, not an edge leaving. → src JSON: start the via column a few px further left (x≈25).
- [产品语义] The main rail numbers nodes 01–04 ("Send"→"Arrival"→"Placement"→"Staking succeeds"), but the diagram's own title and omnichain.md define three stages; step 04 is an outcome, not a stage, and the 01–04 chips imply a four-stage flow. → src JSON: label the success node without a step number (or as "03 ✓ outcome").
- [颜色搭配] Band labels ("01 /", "02 /", "03 /") use `.t-dim` resolved to pure `#ffffff` — identical to node-title white, so the lane-layer hierarchy (band label < node title) is lost in the export; in the HTML they are properly gray via `var(--text-dim)`. → export script: same var-resolution fix as the P1 theming item.

Semantics that check out (verified against omnichain.md, no action): send/arrival/placement vocabulary and order; messaging fee paid exactly on the source chain; burn-on-source/mint-on-destination captured by "Burned, not minted / Stranded; manual recovery"; all three send outcomes (full send, truncated+refunded, fee-inexact/below-minimum revert); bare tokens with "No shares or voting power" when the YieldVault is missing, including the retry-once-in-place note; "Verify YieldVault shares" on success; the three reminder cards are all consistent with the doc.
