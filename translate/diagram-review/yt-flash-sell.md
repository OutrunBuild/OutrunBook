Arrow directions all correct. Layout family (participant x, message rows y=185/235/285/330, palette, legend) is identical to yt-flash-buy — consistent.

Consequences: "Available only during the Locked phase", "One atomic execution…", the fee-on-full-PT-leg warning, and the "Receive y − Q POL; the larger Q, the less you net" restatement exist in no visible pixel of the artifact the chapter embeds (meta.title's "one atomic transaction" survives only as an invisible a11y `<title>`) → export script: render `cards` in the SVG path (or, if SVG is intentionally card-free, strip `cards` from the sequence JSON schema so the dead band is closed and HTML/SVG don't silently diverge).
- [字体] At the authored 820 viewBox: all 3 participant sublabels ("Sets minimum-receive floor", "Reuses liquidity", "1 PT + 1 YT = 1 POL") and all 3 notes ("This Q POL is \"borrowed\"", "Back into y POL", "Displayed price is indicative only; execution follows the pool state at fill time") are `font-size="7"` — illegible at 1x and in print; the four message labels (the core content, incl. "Receive y − Q POL") are only `font-size="9"`. Family inconsistency: yt-flash-buy.svg auto-shrinks the same-role texts to 6.5/6.8, so identical roles render at three different sizes across the pair → export script: raise the type scale at 820 (notes ≥9, sublabels ≥10, message labels ≥11) with a floor so long notes shrink no further than a shared minimum; same fix cures buy.

## P2

- [产品语义] No visible diagram title: meta.title "Sell YT: buy PT → merge → repay POL (one atomic transaction)" renders only as an accessibility `<title>`; in the standalone SVG nothing visible says "Sell YT", and with two chips unreadable (known exporter bug) the first visible action literally reads "Buy y PT" — a standalone reader can mistake this for the buy flow (the buy diagram's first leg is likewise the opposite verb "Sell y PT for R POL") → export script: render the meta.title as a small header line above the participant row; text already in src JSON.
- [颜色搭配] Chip text color ignores the message variant: "Merge y PT + your y YT" is teal (emphasis color) while its arrow is slate "default message"; only message 1 (green text on green request line) matches. The legend teaches color = variant, so the teal chip mislabels the slate leg (buy has the same mismatch on "Put up y POL to split") → export script: derive chip text/border class from the message's variant, not a fixed accent.
- [颜色搭配] Participant header text is white on pastel fills — "PT/POL pool" white-on-lavender and "Merge" white-on-sage are roughly 2:1 contrast, and the 7px white sublabels on the same fills are weaker still → export script: darken the participant fills (or switch header/sublabel ink to near-black) so 11px/7px white text clears ~4.5:1.
- [箭头形状] The request arrowhead (~10×7 units) sits on a 1.5-unit stroke — a ~12:1 head-to-line ratio that reads as a blob at 820 (visible on "Buy y PT for Q POL" and in the legend); return arrowheads are white-filled, which on the dark grid reads as a gap in the dashed line rather than a directed head → export script: scale marker to ~3–4× stroke width and fill return heads with the line color (outline-only if "hollow" is intended).
- [排列布局] The long receive note ("Displayed price is indicative only; execution follows the pool state at fill time", x≈175–515) is crossed mid-sentence by the pool lifeline dashes with no halo or gap, so at 7px the dashes thread between words → export script: give notes a bg-colored halo rect or break the lifeline behind note text.
